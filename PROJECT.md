## ТЗ (техническое задание)

Информация к поездке разбросана: Plotline (места из Instagram/TikTok — всё вперемешку, своих категорий нет, выгрузки нет), сохранёнки в соцсетях, списки Google Maps, Notion, Telegram, заметки и файлы. Нужно одно удобное приложение, куда это сложить и где легко найти нужное в поездке.

**Устройства:** iPhone и Windows, синхронизация; в Японии — работа без сети.

**Разделы:** Еда · Места (достопримечательности, развлечения) · Шопинг · Отели · Гайды (проездные, деньги и обмен, связь, документы, этикет). Плюс «Входящие» — быстро сохранить ссылку, разобрать потом (сам или Claude).

**Места:** в разделе — лента категорий (Бургеры, Якинику, Тонкацу, Темпура…). Пока категория не выбрана — видны все места раздела; выбрал — фильтр. Ещё фильтры: город, «хочу / был / избранное»; поиск по всему. Карточка: фото (с улицы), название, ближайшая станция. Экран места: название по-японски (показать таксисту), адрес, часы, цена, заметка, «Открыть в Google Maps», ссылка на источник (рилс).

**Наполнение:** форма в приложении (с фото) и Claude через CLI (перенос из всех источников, дописывает японские названия, станции, ссылки, фото).

**Доступ:** владелец может пригласить человека с ролью «администратор» (может менять) или «зритель» (только смотрит).

**Карта** — вторым этапом (пока кнопка «Открыть в Google Maps»).

**Критерии готовности (этапы 0–1):** приложение установлено на iPhone и Windows; место с фото, добавленное на телефоне, видно на ПК; фильтр по категории работает как описано; в авиарежиме открываются места и скачанные фото; зритель не может ничего изменить.

## Архитектура

- **PWA** (Vite + Preact + TS), каркас из `life-planner`. GitHub Pages `/japan-guide/`.
- **Supabase — общий проект с «Планером»** (бесплатный проект засыпает после 7 дней без запросов; «Планер» используется ежедневно). Свои таблицы:
  - `jp_members(user_id, email, name, role)` — owner / admin / viewer; функция `jp_role()` для политик.
  - `jp_records(id, kind, data, updated_at, deleted, server_updated_at, created_by)` — общая для всех участников, RLS: читать — любой участник, писать — owner/admin. LWW-триггер как в «Планере».
  - Хранилище `jp-photos` — публичное чтение, запись/удаление — owner/admin.
  - Функция `jp-invite` — приглашение: создаёт вход с временным паролем (регистрация закрыта) и роль.
- **Offline-first:** Dexie, синхронизация как в «Планере». Фото — кэш service worker'а + кнопка «Скачать всё для офлайна».
- **Общий origin с «Планером»:** свой ключ сессии (`jp-auth`), выход только на этом устройстве (`scope: 'local'`).
- **Claude-помощник:** `scripts/japan.ts` (секретный ключ) — места, импорт пачкой с проверкой дублей, категории, гайды, входящие, участники.
